## Contexte

Les endpoints POST de l'API plantent au lieu de répondre 400 quand l'entrée est inattendue. Avec le lancement documenté (`python run.py`, mode debug), la page du débogueur Werkzeug est renvoyée.

## Préconditions

Application lancée ; clé API valide (`quickorder-demo-key`).

## Étapes pour reproduire

1. Envoyer `POST /api/coupons/validate` avec `{"code":"WELCOME10","subtotal":"NaN"}` (puis `"Infinity"`, puis `"1e999"`).
2. Envoyer `POST /api/orders` avec le corps `[1]` (un tableau JSON).
3. Lire le code HTTP et le corps de chaque réponse.

## Résultat attendu

Un code 400 avec un message JSON explicite pour toute entrée invalide.

## Résultat obtenu

HTTP 500 dans chaque cas (`decimal.InvalidOperation` pour les valeurs non finies, `AttributeError` pour le tableau). Le corps est la page HTML du débogueur Werkzeug (traceback et chemins du serveur).

## Preuves

**Rejouer en ligne de commande (API) (commande de rejeu)**

```bash
curl -s -o /dev/null -w '%{http_code}\n' -X POST -H 'X-API-Key: quickorder-demo-key' -H 'Content-Type: application/json' -d '{"code":"WELCOME10","subtotal":"NaN"}' http://127.0.0.1:5000/api/coupons/validate

```

### Rejeu automatique (curl)

Le script `docs/automation/reproduce_bugs.sh` rejoue ce bug et affiche `REPRODUIT` ou `NON REPRODUIT` ; sortie conservée dans [`reproduction-curl.txt`](../evidence/reproduction-curl.txt).

## Analyse

- **Cause probable** : app/routes/api.py : `Decimal(str(payload.get("subtotal")))` accepte NaN/Infinity puis échoue sur `quantize` ; `request.get_json()` n'est jamais vérifié comme objet. run.py active le debug par défaut.
- **Impact** : Indisponibilité d'endpoints et fuite d'informations internes.

## Suggestion de correction

Valider le schéma des entrées (type, valeurs finies), renvoyer 400 JSON et désactiver le mode debug par défaut.
