# BUG-003 — Le paiement en espèces accepte un montant inférieur au total (monnaie négative)

| Champ | Valeur |
|---|---|

| Statut | Ouvert |

| Détecté par | Équipe QA |
| Cas de test liés | TC-RM-06, TC-RM-07, TC-RM-08 |
| Environnement | QuickOrder V3.1 · base seedée (python seed.py) · http://127.0.0.1:5000 · Chromium (Playwright) · Python 3.13 · SQLite |

## Contexte

En paiement « Espèces », l'utilisateur indique le montant remis pour calculer la monnaie.

## Préconditions

Alice connectée (ou clé API) ; total de commande 14,89 €.

## Étapes pour reproduire

1. Ajouter 1 × Classic Burger au panier.
2. Ouvrir /checkout, choisir « Espèces » et saisir 1,00 € comme montant remis.
3. Confirmer la commande et lire le détail.

## Résultat attendu

La commande est refusée : le montant remis doit être ≥ au total (14,89 €).

## Résultat obtenu

La commande est confirmée et payée. Le détail affiche « Montant remis : 1.00 € · Monnaie calculée : -13.89 € ». Un champ vide est traité comme 0 et accepté lui aussi.

## Preuves

**Reproduction API (commande de rejeu)**

```bash
curl -s -X POST -H 'X-API-Key: quickorder-demo-key' -H 'Content-Type: application/json' \
  -d '{"items":[{"product_id":1,"quantity":1}],"payment_method":"cash","cash_received":1}' http://127.0.0.1:5000/api/orders
```

## Analyse

- **Cause probable** : app/routes/orders.py (`build_order`, branche cash) et app/routes/api.py : aucune comparaison `cash_received >= total`.
- **Impact** : Pertes financières à la livraison, données de paiement incohérentes.

## Suggestion de correction

Valider `cash_received >= total` côté serveur (400 / message), rendre le champ obligatoire en espèces, et refuser les montants négatifs ou non numériques.
