## Contexte

Le menu affiche « Stock N » et un bandeau HORS STOCK, mais les règles ne sont pas appliquées.

## Préconditions

Alice connectée (ou clé API) ; Veggie Burger (id 4, stock 0) ; Salmon Bowl (id 7, stock 2).

## Étapes pour reproduire

1. Ouvrir le menu de Burger Factory : Veggie Burger affiche HORS STOCK.
2. Cliquer sur « Ajouter » : le produit entre dans le panier.
3. Ouvrir le menu de Tokyo Bowl, retirer le plafond HTML `max` du champ quantité (DevTools) et ajouter 3 Salmon Bowl (stock 2), puis commander.
4. Revenir sur le menu : le stock est négatif (-1).
5. Même contournement avec 1000 Classic Burger (stock 100), ou, via l'API, deux lignes de 20 pour le produit 1.

## Résultat attendu

Un produit à stock 0 ne peut pas être ajouté ; une quantité supérieure au stock est refusée ; le stock ne devient jamais négatif ; les plafonds de quantité sont identiques partout.

## Résultat obtenu

Produit hors stock ajouté au panier (message « HORS STOCK » affiché mais ajout accepté) ; Salmon Bowl vendu 3 fois pour un stock de 2 (stock final −1 constaté sur le menu) ; quantité 1000 acceptée dans le panier web (sous-total de 11 900 € pour un stock de 100) ; l'API accepte 40 unités en répartissant sur deux lignes (plafond de 20 contourné) et ignore le stock.

## Analyse

- **Cause probable** : app/routes/shop.py (add, cart : « stock=0 is allowed », quantité non plafonnée) ; app/routes/orders.py (add_order_items : `product.stock -= quantity` sans test) ; app/routes/api.py (« forgets the stock quantity »).
- **Impact** : Survente, commandes impossibles à livrer, stock incohérent, risque d'abus (quantités démesurées).

## Suggestion de correction

Centraliser la règle dans un service de commande : refuser si `quantité > stock`, décrémenter avec une mise à jour atomique (`UPDATE … WHERE stock >= :q`), plafonner la quantité unitaire et cumulée.
