## Contexte

L'accueil propose « Livraison max ≤ 2,00 € / 2,50 € / 3,00 € ».

## Préconditions

Visiteur ; base seedée (frais : Green Kitchen 1,99 ; Pizza Roma 2,49 ; Burger 2,99 ; Atlas 2,99 ; Night Sushi 2,99 ; Tokyo 3,49).

## Étapes pour reproduire

1. Ouvrir l'accueil.
2. Choisir « ≤ 2,00 € » dans « Livraison max ».
3. Cliquer sur « Rechercher ».

## Résultat attendu

Seul Green Kitchen (1,99 €) est affiché.

## Résultat obtenu

Avec « ≤ 2,00 € » : Couscous Atlas, Tokyo Bowl, Burger Factory, Pizza Roma et Night Sushi sont affichés, Green Kitchen (1,99 €) disparaît. Avec « ≤ 2,50 € » : Couscous Atlas, Tokyo Bowl, Burger Factory et Night Sushi (frais ≥ 2,50 €) ; Green Kitchen et Pizza Roma (2,49 €) disparaissent. Le filtre renvoie les frais supérieurs au plafond.

## Analyse

- **Cause probable** : app/routes/main.py : `Restaurant.delivery_fee >= max_delivery` au lieu de `<=`.
- **Impact** : Le critère de choix prix est inutilisable ; un client pressé voit exactement l'inverse de ce qu'il demande.

## Suggestion de correction

Remplacer `>=` par `<=` et ajouter un test paramétré sur les trois seuils.
