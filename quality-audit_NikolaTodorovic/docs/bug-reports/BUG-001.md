# BUG-001 — Le paiement PayPal crée deux commandes identiques (web et API)

| Environnement | QuickOrder V3.1 · base seedée (python seed.py) · http://127.0.0.1:5000 · Chromium (Playwright) · Python 3.13 · SQLite |

## Contexte

Parcours critique « acheter ». Le mode PayPal est proposé au checkout et dans POST /api/orders.

## Préconditions

Alice connectée (ou clé API) ; panier : 1 × Classic Burger ; une seule commande existante (#1).

## Étapes pour reproduire

1. Ouvrir /checkout avec 1 × Classic Burger dans le panier.
2. Choisir « PayPal — succès ».
3. Cliquer sur « Confirmer 14,89 € ».
4. Ouvrir /orders.
5. Ouvrir le menu de Burger Factory et lire le stock du Classic Burger.

## Résultat attendu

Une seule commande est créée, débitée une seule fois, et le stock baisse d'une unité.

## Résultat obtenu

Deux commandes distinctes, identiques (même contenu, même total de 14,89 €), apparaissent dans « Mes commandes ». Le client est redirigé vers la première seulement. Le stock du Classic Burger baisse de 2. Le même comportement existe via l'API.

## Preuves

**Reproduction API (commande de rejeu)**

```bash
curl -s -H 'X-API-Key: quickorder-demo-key' http://127.0.0.1:5000/api/orders | jq .count
curl -s -X POST -H 'X-API-Key: quickorder-demo-key' -H 'Content-Type: application/json' \
  -d '{"items":[{"product_id":1,"quantity":1}],"payment_method":"paypal"}' http://127.0.0.1:5000/api/orders
curl -s -H 'X-API-Key: quickorder-demo-key' http://127.0.0.1:5000/api/orders | jq .count
curl -s -H 'X-API-Key: quickorder-demo-key' http://127.0.0.1:5000/api/products/1 | jq .stock
```

## Analyse

- **Cause probable** : app/routes/orders.py (bloc `if payment == "paypal"` : `build_order` + `add_order_items` appelés une seconde fois) ; app/routes/api.py (bloc « PayPal duplicates the order »).
- **Impact** : Double facturation potentielle, double décrément de stock, litiges clients. Atteint directement le chiffre d'affaires et la confiance.

## Suggestion de correction

Supprimer le second appel ; rendre la création de commande idempotente (clé d'idempotence par paiement) et couvrir par un test de non-régression.
