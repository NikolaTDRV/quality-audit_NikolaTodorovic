| Détecté le | 12/10/2026 |
| Détecté par | Équipe QA |
| Cas de test liés | TC-RM-02, TC-RM-03 |
| Environnement | QuickOrder V3.1 · base seedée (python seed.py) · http://127.0.0.1:5000 · Chromium (Playwright) · Python 3.13 · SQLite |

## Contexte

Night Sushi est affiché avec le badge FERMÉ, mais ses produits restent commandables.

## Préconditions

Alice connectée (ou clé API) ; restaurant « Night Sushi » (id 6, fermé).

## Étapes pour reproduire

1. Ouvrir le menu de Night Sushi (badge FERMÉ visible).
2. Cliquer sur « Ajouter » pour Late Sushi Box (14,00 €).
3. Ouvrir /checkout, choisir Carte bancaire et confirmer.

## Résultat attendu

L'ajout ou, au plus tard, la confirmation est refusé avec un message « restaurant fermé ».

## Résultat obtenu

Le produit est ajouté, la commande est confirmée (statut « confirmed », paiement « paid »). Via l'API, POST /api/orders sur le produit 24 renvoie 201.

## Preuves

**Reproduction API (commande de rejeu)**

```bash
curl -s -X POST -H 'X-API-Key: quickorder-demo-key' -H 'Content-Type: application/json' \
  -d '{"items":[{"product_id":24,"quantity":1}],"payment_method":"card"}' http://127.0.0.1:5000/api/orders
```

## Analyse

- **Cause probable** : Aucun contrôle de `restaurant.is_open` dans app/routes/shop.py (add), app/routes/orders.py (checkout) ni app/routes/api.py (create_order_api).
- **Impact** : Commandes impossibles à honorer, clients mécontents, remboursements.

## Suggestion de correction

Contrôler `is_open` à l'ajout au panier, à la validation du checkout et dans l'API (409 avec message explicite) ; désactiver le bouton « Ajouter » sur les restaurants fermés.
